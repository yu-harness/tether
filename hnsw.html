HNSW：从顶层入口逐层下沉

HNSW 论文 Figure 1 的画法，去掉了转载水印

  • entry point —— 顶层入口。搜索从这里出发，这一层只放了极少数节点，用来快速跳到目标所在的大致区域。
  • query vector —— 查询向量。你要找的那个东西，最终落在最底层。
  • nearest neighbor —— 找到的近似最近邻。它和 query 之间还有一小段距离，这是近似检索的固有代价。
  • 蓝色箭头 —— 两层含义：同一层内朝更近的点移动，以及找到局部最优后下沉到下一层继续找。
  • 灰色虚线 —— 同一个元素同时存在于相邻的几层里。往下的每一层都是上一层节点的超集。

三层从上往下越来越密。顶层节点极少、边很长，几步就能跨到目标所在的大区域；越往下节点越多、边越短，用于在局部精细收敛。

搜索过程是"贪心 + 下沉"的循环：在某一层里不断走向离 query 更近的邻居，走不动了就下沉一层，重复，直到最底层。

一个容易看错的点：图上那些蓝箭头大部分是图本身的连边，不完全等于搜索实际走的路径。真正的轨迹是"层内贪心步进 + 跨层下沉"的组合，而且层内搜索可能先靠近再回退，走的不是直线。

这就是它比暴力检索快的原因：不用跟每个点算距离，大部分点根本不会被访问到。Redis 8.0 起内置的 Vector Set 底层用的就是这套结构。
